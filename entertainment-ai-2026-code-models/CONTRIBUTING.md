# 調査の前提・掲載条件・追記手順

この文書は、後から別の人やAIが調査を継続するときの共通基準です。掲載の必須条件は、**著者の公式コードと、本研究で配布する学習済み重みの両方が公開されていること**です。件数を増やすために条件を緩めません。

## 1. 目的と調査範囲

アニメ・エンタメ制作に使える、または制作技術の参考になるAI研究を探します。論文の新しさだけでなく、「何を入力し、何が得られ、制作のどこに役立つか」を日本語で説明できることを重視します。

- 主な対象：中割り・彩色、画像／動画生成・編集、合成・VFX、3D生成・復元、リグ・スキニング、モーション・接触・ジェスチャー、アバター、レンダリング・材質・照明、音声・音楽・効果音。
- 主な会議：SIGGRAPH / SIGGRAPH Asia、CVPR / ICCV / ECCV、ICLR / NeurIPS / ICML、SCA / MIG、ACM MM、ICASSP / Interspeech。対象会議の追加も可能ですが、選んだ理由と採択・発表の根拠を残します。
- ロボット・CAD・製造などの周辺分野は、制作との関係を説明し、完成したアニメ制作ツールであるかのようには紹介しません。
- 元のSIGGRAPH一覧はTechnical Papersを広く調べたものです。他会議の一覧は用途から選んだ候補で、調査の広さが異なります。掲載件数を、その会議の研究総数や充実度の比較に使いません。
- 全採択論文の網羅を前提にしません。「確認した候補では0件」と「該当研究が存在しない」を区別します。

## 2. 年度と採択状況

このリポジトリは**2026年版**です。調査時点で確認できる2026年の採択・発表研究を優先し、2026年大会がない、採択未確定などの場合は2025年を調べます。

1. 年はプレプリント初出年やGitHubの更新年ではなく、採択・発表先の年で分類します。
2. 2026年の状況は調査のたびに公式会議サイトで確認します。以前の「採択通知前」という説明をそのまま引き継ぎません。
3. 2025年を使う理由を、関連会議JSONの`venues`と一覧の年度表に記載します。2026年が公開されたら優先して追加調査し、2025年の有用な研究は年を保持して併記できます。
4. 本会議、Findings、Journal / TOG、開催前の採択告知を区別します。Workshop、ポスター専用枠、講習資料を本会議論文と混同しません。本会議論文の発表形式としてのPosterとは区別します。
5. 著者の採択告知しか確認できない場合は、その旨と根拠を明記します。投稿中の論文を採択済みとして扱いません。
6. SIGGRAPHの既存集はTechnical Papers / 指定TOG発表の範囲を維持します。他トラックを追加する場合は、別枠で掲載範囲を説明します。
7. 同じ研究の公開モデルが更新された場合は、論文版・後継版・確認したモデル版を区別します。重みや推論コードを確認していない後継版まで公開確認済みにしません。

2027年以降を本格的に扱うときは、2026年の記録を書き換えず、年度別データを追加するなど構成を明示的に見直します。

## 3. 掲載可否の判定

| 項目 | 掲載に必要な確認 |
| --- | --- |
| 著者との対応 | 論文・著者／所属機関のページ・公式プロジェクトから実装と重みの関係を確認する。第三者まとめは候補発見に使い、掲載根拠は一次情報にたどる。 |
| コード | リポジトリが存在するだけでは不十分。推論・モデルなどの実装ファイルを読み取れることを確認する。READMEだけ、APIクライアントだけ、デモ画面だけは不可。学習コードの公開は必須ではない。 |
| 重み | 本研究の学習済みモデル、LoRA、ポリシー、判別器、同梱ネットワーク等の配布を確認する。ファイル名・配布説明・実装での利用先を突き合わせる。 |
| 研究固有の公開物 | 依存する既存モデルの重みだけ、データセットだけ、設定ファイルだけ、学習方法だけ、Coming soonは不可。 |
| 部分公開 | 論文の一部の機能でも、その機能の実装と研究固有の重みが両方ある場合は掲載可。何が公開され、何が未公開かを明記し、全機能公開と数えない。 |
| 登録・条件同意 | 一般向けの配布が実在する場合は掲載可。`registration_required` / `terms_acceptance_required`を記録する。個別に著者へ依頼しないと配布の存在を確認できないものは保留。 |
| 利用条件 | 商用利用可は必須条件ではない。コード・重み・依存物の条件を別々に確認し、非商用などの制約を備考へ記す。不明は不明のまま残す。 |

公開情報の確認と、動作・品質の確認は別です。モデルを実行していない場合、「すぐ動く」「再現済み」「日本語対応」「このGPUで動く」「ComfyUI対応済み」と独自に断定しません。著者の公称値・連携案内を載せる場合は、その出典と未検証であることを示します。

## 4. 配布先ごとの確認方法

- **GitHubコード**：コミットSHAを固定し、実装ファイルとREADME・利用条件のURLを記録します。モデル本体を調査のためにリポジトリへ追加する必要はありません。
- **Hugging Face**：モデルカード、ファイル一覧、リビジョンを確認します。研究固有の重みファイルを選び、可能なら配布URLのHEADまたは少量取得で応答を確認します。認証が必要ならその条件を記録します。
- **GitHub Releases / Git LFS**：Release assetや実際の重み配布を確認します。Git LFSのポインタファイルがあるだけで、モデル本体の取得確認済みとはしません。
- **Google Drive / Dropbox / その他**：著者の配布リンクをたどり、共有ページのアーカイブ名・重みファイル名と説明を確認します。HTMLのHTTP 200だけを、重み本体のダウンロード成功としません。
- **応答が不明瞭な場合**：404、権限不足、レート制限、閲覧ツールの制限を区別します。別の公式配布先で確認できなければ保留にし、確認できなかった理由を残します。

`verification`は実施した方法、`http_status`はその対象への実際の応答を記録します。ファイル一覧、配布ページ、サンプル重み、全重み取得、推論実行はそれぞれ別の確認段階です。サンプル1ファイルの成功を全シャードの取得成功に拡張しません。確認していない応答・リビジョン・チェックサムを推測で埋めません。

## 5. 保存先と項目

JSONを確認根拠の正本とし、対応するMarkdownとCSVを同時に更新します。2つのJSONは既存の項目名が異なるため、無関係なスキーマ統一は行いません。

| 対象 | 正本 | 表示・CSV | 保留・未掲載 |
| --- | --- | --- | --- |
| SIGGRAPH 2026の既存範囲 | [papers.json](papers.json) | [README.md](README.md)、[papers.csv](papers.csv) | [reviewed-not-included.json](reviewed-not-included.json) |
| 関連会議 | [entertainment-research-2026.json](entertainment-research-2026.json)の`papers` | [entertainment-research-2026.md](entertainment-research-2026.md)、[CSV](entertainment-research-2026.csv) | 同JSONの`reviewed_not_included`とMarkdownの未掲載表 |

追記時は、同じ配布形態の既存項目を構造の参考にし、値をコピーしたまま残さず、その研究について確認した内容に置き換えます。

| 情報 | 記録する項目・注意 |
| --- | --- |
| 論文 | `title`、`short_name`、`paper_url`。SIGGRAPHは`doi`・`track`、関連会議は`conference`・`year`・`conference_status`。 |
| 内容 | `category`、`summary_ja`。入力→処理→出力と制作用途を1～2文で説明する。宣伝文の直訳や、論文にない能力の付加を避ける。 |
| コード | `code_url`、`code_repository`（owner/repo）、`code_revision`、根拠URL。関連会議は`code_evidence_files`に実装ファイルを記録する。 |
| 重み | 空でない`models`。各配布先の`url`、`access`、`checked_on`、`verification`と、確認したファイル名・配布ページのタイトルなどを残す。取得できる場合は`revision`、実測した応答も記録する。 |
| 公開範囲・依存物 | SIGGRAPHは`notes`、関連会議は`release_scope_ja`・`notes_ja`。別途必要な基盤モデル、登録、部分公開、モデル版、既知の制約を説明する。 |
| 利用条件 | 既存形式のライセンスURL・metadataを記録する。`NOASSERTION`やnullを、自由利用や商用利用可と読み替えない。 |
| 根拠・日付 | `evidence_urls`と項目単位の`checked_on`（YYYY-MM-DD）。可能な箇所はコミット固定URLにする。未確認項目の日付まで一括更新しない。 |

JSON先頭の`checked_on`とページの確認日は、一覧への最終追記・確認日として更新します。全件を同日に再調査したという意味ではありません。判断には各論文・モデルの確認日を使い、部分的な再確認なら範囲を備考に残します。

## 6. 実際の追記手順

1. `git status --short`と適用される指示を確認し、既存変更を保持する。対象会議・年・制作分野と、今回は選定調査か全件走査かを決める。
2. 公式会議一覧、会議録、著者ページから候補を探す。GitHub検索や第三者まとめで見つけた候補も、採択・著者の一次情報へたどる。
3. DOI、論文タイトル、著者、コードURLで既存掲載を検索する。旧題・改題・ミラー・同一論文の別モデルを別研究として重複計上しない。別論文が同じコードを使う場合は関係を説明する。
4. 第3～4節の基準でコードと重みを確認する。両方確認できた候補だけを掲載し、不足する候補は理由・確認日・根拠付きで保留／未掲載に記録する。
5. JSONへ日本語要約と確認根拠を追記し、対応するMarkdown・CSVを更新する。既存の分野に入らない場合のみ分類を追加する。
6. READMEの件数、分野別見出し、関連会議の年度表、JSONの`venues[].included_count`、`scope`などに埋め込まれた件数を更新する。複数年度を併記する場合は会議と年の組を区別する。
7. 会議の新年度や新分野を調べた場合は、公式一覧の根拠URLと調査範囲を`venues`やページの説明へ追記する。未掲載から掲載へ移すときは、古い「未公開」の説明も解消する。
8. 下記の整合性を確認し、変更内容と未検証範囲を報告する。このリポジトリではユーザーの指示によりmainへ直接反映する運用。push前にremoteの更新を確認し、force pushや既存変更の上書きは行わない。

### 追記後の確認

- JSONが読み込める。掲載各件に要約・コード・空でないモデル情報・根拠・確認日がある。
- JSONとCSVの行数・タイトル・要約・URLが一致し、Markdownの掲載件数や会議別・分野別の件数とも一致する。
- 新規項目のコード・モデルURLは実際に確認したもの。Markdownの相対リンクが有効で、表が崩れていない。
- 重複、年度・トラックの誤分類、未掲載理由との矛盾がない。既存項目の根拠を消していない。
- `git diff --check`を実行し、差分が今回の調査・修正範囲に収まる。

文書の追記だけでGPU推論や新しいテストの作成は必要ありません。一時的な調査スクリプト・取得ページ・ログは`/tmp`などリポジトリ外に保存し、不要になった自作の一時物だけを片付けます。

## 7. 次回の調査依頼に使える文面

> CONTRIBUTING.mdの条件に従って、［会議・年・制作分野］の候補を追加調査してください。2026年を優先し、未確定／非開催なら2025年を参照してください。公式コードと本研究の学習済み重みの両方が公開済みのものだけを追加し、日本語の内容要約、公開範囲、確認日、根拠を記録してください。既存掲載との重複を避け、JSON・CSV・Markdown・件数を同期してください。調査範囲と未掲載理由を残し、整合性確認後にmainへpushしてください。
